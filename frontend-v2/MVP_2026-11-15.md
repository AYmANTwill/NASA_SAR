# MVP avec les résultats publiés des collègues

`origin/main` est intégré jusqu’à `7edabcb` : résultats d’Anass (`1558a1f`), water v3 et export des seuls cas finaux.
Les traitements scientifiques et le paquet water ne sont pas modifiés par cette intégration frontend.

Le MVP présente :

- **Bin El Ouidane, final** : couches d’eau avant/après/changement, fonds HLS optiques de l’API sous les couches,
  figures et valeurs/incer­titudes actuelles. `heldout_iou` reste la mesure du modèle ; le score sur un barrage
  jamais entraîné conserve son libellé distinct de l’API. Aucun chiffre de sélection n’est substitué.
- **Haouz, brouillon** : indicateurs GCOV/cohérence/SME2 d’Anass, figure de log-rapport et eau libre U-Net.
  Conclusion « pas de changement net », sans surface inondée revendiquée. L’eau libre sans référence garde
  un badge neutre. Les libellés API distinguent la dispersion du niveau sans événement d’une erreur de mesure.
- **Panama, brouillon** : figure d’Anass du calcul avec la convention +1, instable, sans finding de magnitude.
  Les résultats du signe restent non tranchés ; l’autre signe n’est pas choisi parce qu’il ajuste mieux.
- **Ionosphère, brouillon** : graphique du CSV préliminaire fourni ; aucune validation GPS inventée.
- **Venezuela, brouillon** : les résultats manquants sont signalés.

Les produits bruts/catalogue, rapports GPS et expositions manquants empêchent les quatre derniers cas de devenir
des résultats finaux. `npm run build:demo` refuse toujours un snapshot contenant ces brouillons. La répétition
les conserve ; la démo finale n’exporte que Bin El Ouidane, conformément à la dernière décision de l’équipe.

## Reproduire

Depuis la racine, avec l’environnement backend installé :

```powershell
.venv/Scripts/python.exe tools/prepare_frontend_mvp.py --panama-preview
cd frontend-v2
npm run snapshot
npm run build:rehearsal
npm run package:mvp
```

L’assemblage appelle le générateur officiel `science.cases` ; il ne recalcule pas les traitements sur les H5.
L’entrée Panama est copiée sans modifier les valeurs depuis `results/panama-2026/fault/sign_plus/` vers l’entrée
attendue par ce générateur. Toute entrée existante différente est préservée avec un arrêt explicite.

`dist-rehearsal/START-MVP.cmd` démarre le site sur Windows ; Node.js est requis, aucun `npm install` ni backend.
Sur les autres systèmes : `node dist-rehearsal/serve-mvp.mjs`. Ouvrir `http://127.0.0.1:4312/fr/`.
L’archive locale `NISAR-MVP-2026-11-15.zip` contient ce dossier ; elle est ignorée par Git.

Pour la démo finale, sans promouvoir aucun brouillon : `npm run snapshot:final`, `npm run build:demo`, puis
`npm run package:mvp -- --demo`. L’archive `NISAR-MVP-FINAL-2026-11-15.zip` contient `dist-demo/` avec le même
lanceur autonome. Le filtrage retire les dossiers brouillons du snapshot ; il ne change aucune mesure ni statut.

## Vérifications

TypeScript, ESLint et 131 tests unitaires passent. Les cinq cas, leur liste et les contrôles eau sont vérifiés en
FR/EN/AR, à 1440 et 390 px, avec contrôle d’accessibilité, d’emprise et de chargement des images. Le scénario
historique des placeholders absents est sauté sur cette API, mais reste couvert par les fixtures unitaires.
Les questions préparées et les pages du build de répétition passent sans requête extérieure ; le build normal
est également testé après coupure du réseau, avec les fonds optiques et les superpositions enregistrés.

Captures de revue : `../docs/mvp/screenshots/`. Les limites scientifiques restent celles des fichiers publiés,
et ces contrôles de présentation ne constituent pas une nouvelle validation des traitements scientifiques.
